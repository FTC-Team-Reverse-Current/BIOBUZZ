# The Rules of Programming

- All merges into main need to be reviewed by a lead
- Commiting into non-default branches do not require review
- You have to run the formatter before you pull request
- All tests have to pass before merging into master
- Any inactive branch must be deleted
- Commit messages should describe everything changed, but need to be brief
- Only Kotlin is allowed on these repositories
- Only leads can modify build.gradle files
- Always bring your computer
- **NO VIBE CODING ALLOWED**

## Competition Specific

- Competition branches need to be merged into master after the competition
- Branch PRs should be reviewed by one lead that did not work on the feature
- Branch PRs changing core features need at least 2 leads approval
- Competition PRs need to be approved by at least 2 leads and one programming mentor
- Competition PRs changing core functionality (essential commands, parts of robot container) need approval by all leads
